Executive Dashboard
CO-OP Operations & Intelligence Portal


Executive Page Overview:
The Executive Dashboard is the command center for cross-department operations. It is designed for leadership users who need one place to monitor HR, Product, Finance, Marketing, Inventory, and Chick-fil-A activity, while also managing role-based access and reviewing audit history. The page combines high-level KPIs, operational feed items, AI-assisted analysis, and administrative controls.

The executive experience is permission-aware at every layer. If a user does not have executive-level permissions, they are redirected away from the page. If a user has partial executive permission, they only see the specific tabs and department summaries that match their access.


Main Objectives of the Executive Page:
* Provide one cross-department overview with current metrics and alerts
* Enable fast drill-down into each department’s dashboard
* Support AI-assisted executive summaries and Q&A
* Give executives direct control over role and employee permissions
* Provide an audit trail for accountability and governance
* Keep implementation modular so each department can evolve independently


Executive Navigation and Visibility:
The page is built around tabbed modules. Tabs are shown dynamically based on user permissions.

Primary tabs include:
* AI Agent
* Overview
* HR
* Product
* Finance
* Marketing
* Inventory
* Chick-fil-A
* Audit Log
* Access Control

Visibility logic:
* If the user can access only some departments, only those department tabs are rendered.
* If the user can access Access Control, they can also see the Audit Log tab.
* If no executive tab is allowed for the user, the page shows a permission warning message.

This keeps the UI clean and avoids exposing workflows the user is not allowed to perform.


Executive AI Agent:
The AI Agent tab is built for conversational executive operations. It supports:
* Multi-session chat history (new conversation + reopen existing sessions)
* Persistent user memory facts (stored by user key)
* Conversation context replay per session
* Tool-driven operational responses that can include up-to-date department context

AI agent workflow:
1. User sends a prompt.
2. Prompt is saved to conversation history.
3. Tooling planner identifies needed operational tools.
4. System gathers data from executive overview tooling.
5. Assistant response is returned and stored.
6. Important durable user preferences can be extracted and upserted to memory facts.

Practical executive prompts:
* “What changed this week across all departments?”
* “Show attendance risks and pending HR requests.”
* “Which alerts need executive attention today?”

This module allows executives to ask in natural language instead of manually checking every dashboard.


Executive Overview Module:
The Overview tab loads a unified data model generated by server-side aggregation. It compiles:
* Summary cards (orders, attendance rates, request counts, report counts)
* Operational feed (recent department events)
* Alerts (high-priority items requiring attention)
* Metrics (trend-based KPI snapshots)
* Reports (recent report activity)
* Department health summaries
* Meeting attendance insights (latest meeting and trend under 50%)

Data strategy:
* Uses resilient read helpers so a single data-source issue does not crash the whole overview.
* Supports preferred-table and fallback-table resolution for compatibility with schema changes.
* Converts raw operational rows into executive-friendly summaries.

Executive value:
* Leadership gets a quick status pulse in one screen.
* Users can jump directly into the source department page from summary cards and health blocks.
* Department-level health cards reduce time-to-triage for issues.


Department Drill-Down Tabs:
Executive department tabs act as bridges into each department’s dedicated workspace.

Supported departments:
* HR
* Product
* Finance
* Marketing
* Inventory
* Chick-fil-A

Behavior:
* Department cards and links resolve to each department route (`/hr`, `/product`, `/finance`, `/marketing`, `/inventory`, `/cfa`).
* Executives with department permission can quickly pivot from global view to operational detail.
* If permission is missing, the department is excluded from executive tab navigation.


Access Control Module (RBAC v2):
The Access Control tab is the admin surface for role and employee permission management.

Core features:
* Role editor mode and employee editor mode
* Role CRUD-style updates (name, description, active state, permissions)
* Permission toggling by department/resource/action
* Baseline role preset application
* Employee role assignment (primary + secondary roles)
* Optional employee password reset/update
* Employee creation with default self-service role assignment

Security details:
* Viewing access config requires executive access-view permission.
* Editing access config requires executive access-manage permission.
* Password updates are hashed server-side using `scrypt` with per-password salt.
* Update timestamps are used to detect stale drafts and reduce accidental overwrite risk.

Operational impact:
* Executives can quickly grant/revoke capability without editing SQL manually.
* Role templates and centralized permissions reduce privilege drift.
* This module is the primary governance point for least-privilege access.


Executive Audit Log Module:
The Audit Log tab provides cross-department traceability using filtered log views.

Current unified sources:
* `hr_audit_log`
* `finance_report_activity_log`

Filter options:
* Date range
* Department
* Source
* Actor
* Action
* Table name

Capabilities:
* Cursor-based pagination for large result sets
* Department inference from table naming patterns

Executive use cases:
* Investigating who changed records and when
* Verifying compliance and policy adherence
* Tracking unusual activity patterns before they become incidents


Permission and Security Design:
The executive page relies on fine-grained permission checks rather than role-name checks in the UI.

Examples of permission keys used by the executive layer:
* `executive.overview:view:all`
* `executive.ai:view:own`
* `executive.access:view:all`
* `executive.access:manage:all`
* `executive.audit:view:all`

Design principles:
* UI visibility is permission-driven
* API routes enforce permission checks server-side
* Multi-role assignment supports shared responsibilities
* Baseline roles can be adjusted while preserving system defaults

This model improves maintainability and reduces accidental overexposure of tools/data.


Minimal SQL (Reference):
Below are representative SQL snippets that capture the minimum database structure behind executive functionality.

1) Core RBAC tables used by executive access control:

CREATE TABLE IF NOT EXISTS public.access_roles (
  role_key TEXT PRIMARY KEY,
  role_name TEXT NOT NULL,
  description TEXT,
  is_system BOOLEAN NOT NULL DEFAULT FALSE,
  is_active BOOLEAN NOT NULL DEFAULT TRUE,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE TABLE IF NOT EXISTS public.access_role_permissions (
  role_key TEXT NOT NULL REFERENCES public.access_roles(role_key) ON DELETE CASCADE,
  permission_key TEXT NOT NULL REFERENCES public.access_permissions(permission_key) ON DELETE CASCADE,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  PRIMARY KEY(role_key, permission_key)
);

CREATE TABLE IF NOT EXISTS public.employee_role_assignments (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  employee_id BIGINT NOT NULL REFERENCES public.students(id) ON DELETE CASCADE,
  role_key TEXT NOT NULL REFERENCES public.access_roles(role_key) ON DELETE CASCADE,
  is_primary BOOLEAN NOT NULL DEFAULT FALSE,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  UNIQUE(employee_id, role_key)
);

2) Executive AI memory/history tables:

CREATE TABLE IF NOT EXISTS public.executive_agent_memory_facts (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_key TEXT NOT NULL,
  fact_text TEXT NOT NULL,
  category TEXT NOT NULL DEFAULT 'context',
  importance SMALLINT NOT NULL DEFAULT 3 CHECK (importance BETWEEN 1 AND 5),
  source_session_id TEXT NULL,
  last_seen_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE TABLE IF NOT EXISTS public.executive_agent_messages (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_key TEXT NOT NULL,
  session_id TEXT NOT NULL,
  role TEXT NOT NULL CHECK (role IN ('user', 'assistant', 'system')),
  content TEXT NOT NULL,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

3) Minimal grant mapping for executive manager role:

INSERT INTO public.access_role_permissions (role_key, permission_key) VALUES
  ('executive_manager','executive.overview:view:all'),
  ('executive_manager','executive.ai:view:own'),
  ('executive_manager','executive.access:view:all'),
  ('executive_manager','executive.access:manage:all'),
  ('executive_manager','executive.audit:view:all')
ON CONFLICT (role_key, permission_key) DO NOTHING;


Executive Functional Summary:
In production terms, the executive page delivers three layers at once:
* Intelligence Layer: unified overview + AI synthesis
* Governance Layer: RBAC management + access assignment
* Accountability Layer: cross-source audit visibility

That combination turns the Executive Dashboard from a static reporting page into an operational control surface. As the CO-OP expands features in each department, the executive page remains the central orchestration point for leadership decisions, access governance, and incident-aware oversight.
